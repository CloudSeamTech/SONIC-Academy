# Readable steps, machine roles and certification connections

The interface uses IBM Plex Mono at regular weight for reading and its real bold weight for headings. Code keeps JetBrains Mono. Headings and Start here have larger sizes, separate margins and upright bold lettering. Shared instructional panels keep the darker cream surface and receive consistent padding; purple controls retain white labels.

Instructional actions and Start here expand known machine names into their job followed by the exact name. This is presentation only: copied command blocks, FQDNs, paths, downloads and screenshots are unchanged.

For the private Windows help desk, the application server (APP01) is the computer; app01.lab.example.test is its computer FQDN. helpdesk.lab.example.test is the application's browser address, resolving to the same recorded IP and matched by the IIS binding. These are fictional private lab examples, not instructions to publish or rename the academy's real domain.

osTicket cannot use Microsoft SQL Server as its database. Its official installation page requires MySQL and offers MariaDB for Windows: https://docs.osticket.com/en/latest/Getting%20Started/Installation.html . The Windows lab remains IIS + PHP + osTicket + MariaDB. A Linux installation would use a Linux web server and separate Linux commands. This change does not claim to add a complete Linux osTicket course. SQL Server practice remains a separate workload and database.

Certification notes use the current official AZ-104 and AZ-802 study guides and Red Hat's RHCSA page. AZ-802 is the Windows Server administration reference currently linked by Microsoft's Windows Server Hybrid Administrator certification page. Notes support relevant skills, not a claim of complete exam coverage. No forced exam badge is added to product-specific ticket handling, MECM, desktop gaming, or unrelated enrichment lessons. AlmaLinux practice is not presented as the official Red Hat exam environment.

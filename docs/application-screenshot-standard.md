# Application walkthrough media

An instruction card with a title, arrows and numbered text is not a useful substitute for the program's interface. Generated step maps are archived assets and must not automatically fill screenshot slots.

For Windows, VMware and other application steps:

1. Name the computer, application and dialog/page the student should already see.
2. Give the actual control label and exact action: click, select, type or press. Put branching instructions before the click that leaves that page.
3. Identify the next page or visible result. Keep a brief reason beside the action; put optional troubleshooting below it.
4. Add media only when it matches that step's actual application, version and state. Use genuine local captures or an accurately matched vendor reference with attribution. A recreated interface requires an explicit mockup label and separate review; it must never be called a genuine screenshot.
5. Number only the relevant controls and explain every number shown. Do not show another OS, the wrong wizard choice or an application before installation just to fill space.
6. Review the source image against the exact current instruction hash before registering it. Changed instructions invalidate approval. No reviewed capture means the readable click checklist stands alone, without an empty image frame or a duplicate text picture.

The shared legacy walkthrough renderer now accepts only reviewed PNG captures under `/lab-screenshots/captures/` whose step ID and instruction hash match the compact index generated by the screenshot coverage audit. No capture was created or approved by this policy change. Existing separately reviewed course screenshots remain subject to their own step-association gate.
